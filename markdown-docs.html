🔐 Xác thực & Phân quyền Backend

Hệ thống JWT authentication bảo vệ toàn bộ API. Hỗ trợ 2 phương thức đăng nhập: mật khẩu tĩnh và OTP qua messaging.

Đăng nhập bằng mật khẩu Kiểm tra credentials so với biến môi trường ADMIN_USERNAME / ADMIN_PASSWORD. Trả về JWT token có thời hạn 24 giờ.
Đăng nhập bằng OTP Tạo mã 6 số, lưu in-memory (TTL 5 phút), gửi tới user qua Facebook Messenger hoặc Telegram dựa trên channel được chọn.
JWT Middleware Middleware verifyJWT kiểm tra token ở header Authorization: Bearer <token>. Frontend lưu token trong localStorage.
Route bảo vệ Tất cả route trừ /health, /auth/* và webhook verification đều yêu cầu JWT hợp lệ.
MethodEndpointMô tả
POST/api/auth/loginĐăng nhập bằng username + password
POST/api/auth/otp/requestYêu cầu mã OTP (channel: facebook | telegram)
POST/api/auth/otp/verifyXác thực mã OTP → nhận JWT

🤖 Dịch vụ AI Backend

Sử dụng Groq API (OpenAI-compatible) với model llama-3.3-70b-versatile để phân tích ngôn ngữ tự nhiên và trích xuất dữ liệu có cấu trúc.

Phân loại tự động Nhận văn bản đầu vào (VD: "Ăn phở 50k"), trả về JSON gồm category ("chi tiêu" | "ghi chú"), title, value, date.
JSON Response Format Sử dụng response_format: { type: "json_object" } để đảm bảo AI luôn trả JSON hợp lệ, không trả text thô.
MethodEndpointMô tả
POST/api/ai/generateGửi prompt → nhận JSON phân loại (rate limit: 20 req/phút)

💬 Webhook Messaging Backend

Tích hợp với Telegram Bot API và Facebook Messenger Platform. Nhận tin nhắn → phân tích AI → log kết quả → phản hồi user qua cùng kênh.

Telegram Bot Nhận webhook POST, trích xuất text, gọi AI, gửi phản hồi HTML. Tự động nhớ chatId để gửi OTP sau này.
Facebook Messenger Xác thực webhook bằng verify token. Nhận message events, xử lý tương tự Telegram. Nhớ senderId vào file JSON.
Recipient Memory Lưu cache ID người nhận (Telegram chatId, FB senderId) vào file JSON trong thư mục data/ để dùng cho OTP.
Dual Logging Mỗi tin nhắn được log song song ra cả Notion database và Postgres (nếu bật). Lỗi AI cũng được log với category "error".
MethodEndpointMô tả
GET/api/webhook/messengerXác thực webhook Facebook (hub.verify_token)
POST/api/webhook/messengerNhận tin nhắn từ Messenger → AI → phản hồi
POST/api/webhook/telegramNhận tin nhắn từ Telegram → AI → phản hồi

📊 Logging & Lịch sử Backend

Lưu trữ lịch sử tương tác AI vào dual storage: Notion database (chính) và PostgreSQL (tùy chọn).

Notion Logging Sử dụng @notionhq/client để tạo page trong Notion DB. Map các field: Prompt, Category, Title, Value, Date thành Notion properties.
Postgres Logging Kích hoạt bằng ENABLE_POSTGRES_STORAGE=true. Insert bản ghi vào bảng logs song song với Notion. Hỗ trợ cả connection string lẫn host/port/db riêng lẻ.
Xem lịch sử API GET /api/logs đọc từ Notion, trả danh sách các bản ghi gần nhất cho Dashboard hiển thị.
Migration System Script migrate.ts quản lý schema DB: tracking bảng _migrations, chạy các file SQL theo thứ tự, hỗ trợ rollback on failure.
MethodEndpointMô tả
GET/api/logsLấy lịch sử tương tác từ Notion
GET/api/healthHealth check — trả version và uptime
Files: controllers/log.controller.ts · controllers/health.controller.ts · services/notion.service.ts · services/postgres.service.ts · migrate.ts · migrations/*.sql

🎯 Identity & Votes Backend Frontend

Tính năng theo dõi thói quen (habit tracking). Người dùng khai báo một "Identity" (tuyên bố bản thân), sau đó tạo và theo dõi các "Votes" (hành động hàng ngày) để xây dựng chuỗi streak.

Identity Profile Mỗi user có 1 bản ghi Identity chứa text tuyên bố. Tạo mới hoặc cập nhật qua PUT /api/identity.
Habit Votes Tạo các habit (vote items), đánh dấu "đã làm hôm nay" bằng toggle. Mỗi ngày mỗi vote chỉ có thể toggle 1 lần (composite PK: vote_id + vote_date).
Streak Tracking Tính chuỗi ngày liên tiếp (calcStreak), theo dõi hoạt động 7 ngày gần nhất, cảnh báo khi bỏ lỡ 2 ngày liên tiếp (shouldWarnNeverMissTwice).
Frontend Component Component IdentityVotes.tsx hiển thị identity, danh sách votes, nút toggle hàng ngày, streaks, và indicator cảnh báo.

🛡️ Middleware & Bảo mật Middleware

Các tầng cross-cutting concern xử lý bảo mật, validation, rate limiting, logging, và CORS trước khi request đến controller.

Rate Limiting 2 limiter riêng biệt: AI endpoint (20 req/phút), Webhook endpoints (100 req/phút). Sử dụng express-rate-limit.
Request Validation Middleware validateBody dùng Zod schema để validate request body. Trả 400 kèm error messages nếu không hợp lệ.
Structured Logging Logger pino ghi log có cấu trúc (JSON) cho toàn bộ request lifecycle và errors.
CORS Dynamic origin từ CORS_ORIGIN env var trong production. Development cho phép mọi origin.
Files: middlewares/authMiddleware.ts · middlewares/rateLimiter.ts · middlewares/validate.ts · middlewares/logger.ts · schemas/*.ts

🚀 Hạ tầng & Triển khai Infra

Hỗ trợ 3 mô hình triển khai: local dev (Vite HMR), serverless (Vercel), và container (Docker/VPS).

Local Development server.ts chạy Express + Vite middleware với HMR. Frontend proxy API calls tới cùng port. Chạy bằng npm run dev → tsx server.ts.
Vercel Serverless api/index.ts export Express app, vercel.json rewrite /api/* tới serverless function. Branch main-vercel auto-deploy.
Docker / VPS Multi-stage Dockerfile: build frontend → compile server → runtime image tối giản. Docker Compose bao gồm app + Postgres. Health check bằng curl.
CI/CD (GitHub Actions) Workflow ci.yml: type check → test (với Postgres service container) → deploy VPS qua SSH (branch main) hoặc Vercel (branch main-vercel).
Database Migrations Script migrate.ts hỗ trợ up (chạy migrations) và status (xem trạng thái). Tracking qua bảng _migrations.
Telegram Webhook Setup Script scratch/set-telegram-webhook.ts gọi Telegram API để đăng ký webhook URL cho bot.
Files: server.ts · api/index.ts · Dockerfile · docker-compose.yml · vercel.json · .github/workflows/ci.yml · migrate.ts · scratch/set-telegram-webhook.ts
